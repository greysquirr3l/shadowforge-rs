# T22 — Dead drop mode: platform-aware cover generation for public posting

> **Depends on**: T-compression-survivable, T-cover-profile-matching.

## Goal

Implement DeadDropEncoder: produce stego covers specifically optimised for posting to public platforms. No direct file transfer between parties — the sender posts publicly, the recipient retrieves by URL.

## Project Context

- Project: `shadowforge-rs` — shadowforge-rs is a production-grade quantum-resistant steganography toolkit
for journalists, whistleblowers, and dissidents operating against nation-state
adversaries. It is a ground-up Rust reimplementation of shadowforge (Go).

Architecture: Collapsed Hexagonal / DDD-lite — a Cargo workspace mono-repo
with all crates under crates/. Current scope is a single main crate
(crates/shadowforge) with four top-level modules (domain/, adapters/,
application/, interface/) and bounded contexts inside domain/. The workspace
structure is intentional: future crates (shadowforge-web, shadowforge-api,
etc.) add as new members under crates/ without restructuring anything.

Key improvements over the Go version:

- PDF is a first-class bounded context (embed/extract, native watermarking,
    render-to-PNG pipeline, cover-medium via content-stream LSB).
- PQC uses ml-kem and ml-dsa (pure Rust NIST finalists) — no CGo, no CIRCL.
- All bounded contexts share a single coherent type vocabulary in
    domain/types.rs — no duplicate types across contexts.
- Error handling is total: thiserror throughout, zero panics in non-test code.
- All text operations are grapheme-cluster-safe via unicode-segmentation.

### Architecture: Hexagonal (Ports & Adapters)

- **Domain layer** (`domain/`): Pure business logic, no I/O dependencies
- **Ports** (`ports/`): Trait boundaries that define capabilities the domain needs
- **Adapters** (`adapters/`): Implementations of ports (HTTP, DB, filesystem, etc.)
- Keep domain types free of framework-specific derives (no `#[sqlx::FromRow]` etc.)
- Depend inward: adapters → ports ← domain

## Strategy: TDD (Red-Green-Refactor)

### 1. RED — Write failing tests first

- encode_for_platform for Instagram: assert output JPEG is parseable, payload survives simulated Instagram recompression, chi-square score < raw embed.
- encode_for_platform for Telegram with PNG: payload survives pass-through (identical bytes).
- RetrievalManifest serialises to JSON cleanly.
- Profile matching applied: output JPEG quant tables match a known camera profile.

### 2. GREEN — Implement to pass

- DeadDropEncoderImpl implements DeadDropEncoder in src/adapters/deadrop.rs.
- encode_for_platform: 1) Select or accept a cover image. 2) Apply CoverProfileMatcher to match a plausible camera profile. 3) Apply CompressionSurvivableEmbedder for the target platform. 4) Apply AdaptiveOptimiser to minimise detectability. 5) Return the final cover ready for public posting.
- The output of encode_for_platform is a file that: looks like a genuine photograph, matches a real camera model's statistical fingerprint, survives the target platform's recompression, and still yields the payload after platform recompression.
- Add a --dead-drop-url <url> CLI flag (Phase 13): after embedding, print the retrieval URL that the recipient should use. If the platform is Instagram, print the expected public URL format.
- RetrievalManifest: a small JSON struct { platform, retrieval_url, technique, stego_hash } that the sender can share out-of-band (e.g. in a separate steganographic channel). Add to domain/types.rs.
- Platform Telegram: since Telegram passes PNG losslessly, a simple LsbImage embed suffices. Document this as a zero-overhead dead drop path.

### 3. REFACTOR — Clean up while green

- Remove duplication
- Improve naming and structure
- Keep all tests passing
